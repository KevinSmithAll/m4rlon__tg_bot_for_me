## 📌 О проекте

**M4RLON** — персональный Telegram-бот, созданный для решения повседневных задач и постепенного расширения возможностей личного цифрового помощника.

Проект объединяет работу с финансами, получение полезной информации и инструменты автоматизации в одном интерфейсе — без необходимости постоянно переключаться между разными приложениями.

Это также мой практический проект для изучения Python, Git и GitHub: от написания отдельных функций до организации структуры приложения и работы с базой данных.

> 💡 **Главная идея:** технологии должны упрощать жизнь, а не создавать дополнительные задачи.

### 🎯 Основные цели

- 🧠 Развивать персонального цифрового помощника.
- 💰 Упростить учёт личных расходов.
- 🔔 Вынести полезные повседневные функции в Telegram.
- 🗄️ Научиться работать с базами данных и хранением информации.
- 🛠️ Практиковаться в разработке, рефакторинге и сопровождении Python-проектов.

## ✨ Возможности

### 💸 Управление финансами

Следи за личными расходами и работай с финансовыми данными прямо через Telegram.

- Добавление финансовых транзакций.
- Категоризация расходов.
- Настраиваемые категории и лимиты.
- Получение данных о расходах за последние семь дней.
- Подсчёт сумм по категориям.
- Редактирование и удаление записей.
- Экспорт данных в Excel.

### 🌦️ Полезная информация

Бот включает функции получения прогнозной информации о погоде. В проекте также предусмотрена функция, связанная с погодным сообщением в определённое время.

### ⏰ Напоминания

Отдельный модуль предназначен для работы с напоминаниями — чтобы постепенно превращать бота из простого набора команд в полноценного помощника.

### 🔐 Персональный доступ

Бот изначально рассчитан на использование одним владельцем. Для ограничения доступа предусмотрена проверка идентификатора пользователя.

Это позволяет сосредоточиться на персональном сценарии использования, не усложняя проект полноценной системой пользователей.

## 🚀 Установка и запуск

### 1. Подготовь окружение

Установи Python и Git, затем клонируй репозиторий:

```bash
git clone https://github.com/KevinSmithAll/m4rlon__tg_bot_for_me.git

cd m4rlon__tg_bot_for_me
```

### 2. Создай виртуальное окружение

**Windows:**

```powershell
python -m venv .venv
.venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установи зависимости

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Настрой конфигурацию

Перед запуском подготовь необходимые параметры:

- токен Telegram-бота, полученный через [@BotFather](https://t.me/BotFather);
- ID пользователя, которому разрешён доступ;
- API-ключи используемых внешних сервисов;
- остальные настройки, необходимые подключённым функциям.

**Важно:** перед запуском проверь, как параметры загружаются из `config.py`. Для безопасного локального запуска секреты следует хранить в переменных окружения или отдельном конфигурационном файле, исключённом из Git.

Не публикуй токены и API-ключи в репозитории.

### 5. Запусти бота

Основной файл запуска — `main.py`.

```bash
python main.py
```

Если запуск завершается ошибкой, проверь установку зависимостей, настройки конфигурации и доступность внешних API.

## 🔄 Как устроена работа с данными

Для финансового модуля используется SQLite — встроенная реляционная база данных, не требующая отдельного сервера.

Записи о транзакциях включают:

- идентификатор записи;
- сумму;
- дату;
- категорию;
- комментарий.

На уровне класса `Database` предусмотрены операции добавления, получения, изменения и удаления записей. Также есть возможность получить транзакции за последние семь дней и выгрузить данные в Excel.

Такой подход позволяет хранить финансовую историю локально и постепенно развивать аналитику без необходимости сразу внедрять сложную инфраструктуру.

## 🔒 Безопасность

Безопасность — важная часть любого проекта, который взаимодействует с Telegram и внешними API.

- 🔑 Не хранить токены и секретные ключи в открытом виде в исходниках.
- 🚫 Не добавлять `.env`, локальные базы с личными данными и другие секреты в Git.
- 👤 Проверять права доступа перед выполнением чувствительных операций.
- 🧾 Создавать резервные копии важных данных.
- 🔄 Регулярно проверять зависимости и обновлять их при необходимости.

Если токен или API-ключ уже попал в публичный репозиторий, простого удаления из файла недостаточно: необходимо отозвать или перевыпустить секрет и проверить историю Git.
